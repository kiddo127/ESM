# ESM-RoBERTa: Essential Subspace Merging for Language Models

This repository implements two complementary methods for multi-task model merging:

- **ESM** (Essential Subspace Merging): Fuses multiple task-specific models into a single merged model via subspace decomposition and Procrustes orthogonalization.
- **ESM++** (Essential Subspace Merging and Mixture): Builds a dynamic Mixture of Experts from task-specific models, routing each input to the best expert via prototype-based cosine similarity.

Based on [RoBERTa](https://arxiv.org/abs/1907.11692) fine-tuned on 8 GLUE tasks.

## Data and Model Preparation

For detailed instructions on fine-tuning RoBERTa experts and preparing GLUE test data, refer to the [WUDI-Merging](https://github.com/nathanielyvo/WUDI-Merging) project.

### Validation Data

**You must run the following command before using ESM/ESM++.** It generates `data/validation.json`, which is required for computing principal directions (ESM) and collecting routing prototypes (ESM++):

```bash
python prepare_validation.py
```

This tokenizes all 8 GLUE validation sets and saves them to `data/validation.json`. The script uses RoBERTa tokenizer with `padding=False` for efficient storage; sequences are padded dynamically at inference time via `rnn.pad_sequence`.

### Directory Layout

Place the prepared files in the following structure:

```
ESM-RoBERTa/
├── config/
├── run_merge.py
├── prepare_validation.py
├── ...
├── data/
│   ├── test.json              # GLUE test data
│   └── validation.json        # Generated by prepare_validation.py
├── outs/
│   ├── merge_results/         # Results output (created automatically)
│   └── esm_merged/            # ESM merged model (created after merge)
└── ../roberta/                # Finetuned models (relative to project root)
    └── {task}/
        └── roberta-base_lr1e-05/
            ├── config.json
            ├── model.safetensors
            └── classifier_head.pt
```

The 8 GLUE tasks are: `cola`, `sst2`, `mrpc`, `stsb`, `qqp`, `mnli`, `qnli`, `rte`.

For roberta-large, use `../roberta_large/{task}/roberta-large_lr1e-05/`.

The model root is configurable via the `MODEL_ROOT` env var (default `../roberta`; use `MODEL_LARGE_ROOT` for large models), and the data directory via `DATA_ROOT` (default `data`).

## Usage

### ESM (Merging)

Fuse multiple task-specific models into one merged checkpoint, then evaluate:

```bash
bash run_esm.sh
```

Or with custom parameters:

```bash
source scripts.sh
CUDA_VISIBLE_DEVICES=0 seed=0 prototype_proxy_num=32 esm
```

Key parameters:
| Parameter | Default | Description |
|-----------|---------|-------------|
| `select_merge` | 8 | Number of tasks to merge |
| `seed` | 10 | Random seed |
| `prototype_proxy_num` | 32 | Proxy samples per task for PCA |
| `principal_data_path` | `data/validation.json` | Data for principal direction |
| `save_path` | `outs/esm_merged` | Merged model output path |

After merging, the model is saved to `save_path` and evaluated on `data/test.json`.

### ESM++ (Routing)

Use the ESM merged model as base, extract per-task experts, and route dynamically:

```bash
bash run_esm_pp.sh
```

Or with custom parameters:

```bash
source scripts.sh
CUDA_VISIBLE_DEVICES=0 rank=8 seed=0 prototype_proxy_num=32 \
    merged_model_path=outs/esm_merged esm_pp
```

Key parameters:
| Parameter | Default | Description |
|-----------|---------|-------------|
| `rank` | 32 | Expert low-rank dimension (same as ViT; `0` = auto d/T) |
| `mode` | `route` | Routing mode: `route` / `base` |
| `merged_model_path` | `outs/esm_merged` | Base model for MoE |
| `prototype_proxy_num` | 32 | Proxy samples per task for routing prototypes |

**Modes:**
- `route` — prototype-based cosine similarity routing (default)
- `base` — no routing, run the base merged model directly

ESM++ inference is fixed to the fastest path — three parts together:

1. **structured router** — each routed `nn.Linear` is replaced by a real shared
   `MoERoutedLinear` `nn.Module`, so `torch.compile` emits **one** graph per shape
   (the old monkey-patch design produced one closure per layer → 72 specialised
   graphs → 9–13× disaster under compile);
2. **factored expert application** — `x@(U@V)ᵀ == (x@Vᵀ)@Uᵀ` with `U`/`V` kept
   resident on GPU, so no per-sample `[B, d_out, d_in]` dense weight is materialised
   (the dense path's weight traffic grows ∝ B);
3. **`torch.compile(model.roberta, mode="reduce-overhead")`** — encoder only; the
   per-task classifier head stays eager so it can be swapped without re-capturing.

Together this runs at ~1× the base latency. Configure with environment variables:

| Env var | Default | Description |
|:--|:--|:--|
| `ESM_K` | `8` | prototype clusters per task (`1` = single mean prototype; `task:k,...` for per-task counts) |
| `ESM_PROTO_SRC` | `base` | prototype source: `base` (ESM-fused model) or `finetune` |
| `ESM_POOL` | `mean` | layer-input pooling: `mean` or `cls` |
| `ESM_COMPILE` | `1` | wrap the encoder in `torch.compile` (falls back to eager if unavailable) |

### Output

Results are saved to `outs/merge_results/results.csv` and `results.md`, including per-task and average scores.

ESM++ additionally saves routing accuracy to `routing_accuracy_rank{rank}_seed{seed}.json`.
